XFCE Window Manager: Silent Failure & Forensic Recovery

This page explains why an XFCE desktop suddenly lost all window decorations, Alt-Tab, and window controls, how we diagnosed the cause, and how we fixed it in a way that survives reboots. No prior knowledge of X11, window managers, or compositors is assumed.

The short answer

The window manager — xfwm4, the program that draws title bars, borders, and buttons and handles Alt-Tab — was not running. It failed to start on every login because the X display server was not advertising an optional feature called RENDER that xfwm4 needs when it tries to start its compositor. With no window manager, there were no decorations and no Alt-Tab.

The fix is to tell xfwm4 not to start the compositor, and to tell GTK applications to let the WM draw their decorations (GTK_CSD=0) so the black border stops appearing.

Glossary

Window manager (WM)

The program that draws title bars, borders, and buttons, and handles Alt-Tab. Without it, applications draw content but nothing frames them. On XFCE the WM is xfwm4.

X11 / Xorg (display server)

Owns the screen, keyboard, and mouse. Xorg is the classic server; Xwayland is the Wayland compatibility layer. DISPLAY=:0.0 means X11.

Compositor

Optional layer that blends every window's pixels into one image. It enables transparency, shadows, and smooth animations. Without it, semi-transparent pixels paint solid.

RENDER / XRender

An X11 extension (all caps RENDER) providing alpha blending. The library that talks to it is libXrender. A machine can have the library installed while the server does not offer the extension — that is exactly this case.

xfconf-query

Reads and writes XFCE's per-user settings database. xfconf-query -c xfwm4 -p /general/use_compositing reads the compositor setting.

CSD / SSD

CSD: the application draws its own title bar (modern GTK default, needs a compositor for shadows). SSD: the window manager draws it (classic X11, no compositor needed).

environment.d

~/.config/environment.d/*.conf sets session environment variables. Plain NAME=value per line, no export. Read at login by systemd --user.

GTK

The toolkit behind Thunar, Mousepad, the panel, and Firefox. GTK3+ defaults to CSD, which is why the black border appears without a compositor.

The fix, line by line

1. Start the WM with the compositor disabled

setsid nohup xfwm4 --compositor=off >/tmp/xfwm4.log 2>&1 </dev/null &
  • setsid — new session, no controlling terminal; the WM survives terminal close.
  • nohup — ignore SIGHUP on logout.
  • --compositor=off — skip the code path that needs RENDER.
  • >/tmp/xfwm4.log 2>&1 </dev/null & — log both streams, detach stdin, background.

2. Make the setting survive logout

xfconf-query -c xfwm4 -p /general/use_compositing -s false

Persisted in XFCE's user settings DB; the next login reads it and starts xfwm4 without the compositor.

3. Disable CSD (fixes the black border)

export GTK_CSD=0

4. Persist across sessions

mkdir -p ~/.config/environment.d
printf 'GTK_CSD=0\n' > ~/.config/environment.d/10-gtk-csd.conf

Why disabling the compositor removes the black border

With CSD the application draws its own title bar plus a semi-transparent shadow. Without a compositor nothing blends the transparency, so the shadow paints solid black. Setting GTK_CSD=0 tells the application to stop drawing decorations; the WM draws plain ones instead.

Forensic monitoring

statedrift — tamper-evident snapshots

sudo statedrift init
sudo statedrift snap
statedrift diff HEAD~1 HEAD

configsnap — Fedora-native baseline

sudo dnf install -y configsnap
sudo configsnap -t mychange -p pre  -d /var/log/configsnap -v
# ... change ...
sudo configsnap -t mychange -p post -d /var/log/configsnap -v
sudo configsnap -C --pre=pre -p post -t mychange -d /var/log/configsnap -v

Phases with post or rollback diff automatically. -C re‑diffs existing files without recollecting.

tibet-snap — cryptographic snapshots + rollback plans

python3 -m pip install --user tibet-snap
tibet-snap create baseline /etc/X11 /etc/systemd /etc/xdg
tibet-snap list
tibet-snap verify <id>
tibet-snap compare <id_a> <id_b>

Rollback plans are exposed via the Python API, not the CLI:

python3 - <<'PY'
from tibet_snap import SnapEngine
engine = SnapEngine(store_dir=".tibet-snap")
snap = engine.create_snapshot("pre-deploy", paths=["/etc/X11"])
for action in engine.rollback_plan(snap.id):
    print(action["action"], action["path"])
PY

If this happens again

  1. No decorations, Alt-Tab dead. pgrep -x xfwm4.
  2. Start it manually. setsid nohup xfwm4 --compositor=off >/tmp/xfwm4.log 2>&1 </dev/null &; then re-apply the persistent setting.
  3. WM still dies immediately. /tmp/xfwm4.log; if empty, xdpyinfo | grep -i render.
  4. Decorations back but menus black. Add GTK_CSD=0 and log in again.
  5. Need evidence. bash scripts/forensic-baseline.sh; produces .tar.gz.
