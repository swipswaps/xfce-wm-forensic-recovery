XFCE Window Manager: Silent Failure & Forensic Recovery

Fedora 43 · XFCE 4.20 · xfwm4 · Intel Ivy Bridge · X11

No secrets. No hostnames, IPs, or credentials.

How we got here

1. Symptoms

  • Lost window decorations.
  • Alt-Tab failed on all programs.
  • Black border around the Applications dropdown.
  • Firefox min/max buttons failed.

2. Diagnostics (RENDER, not XRender)

pgrep -x xfwm4
pgrep -x xfce4-session
xdpyinfo | grep -i render

3. Root cause

xfwm4 4.20 aborts before opening its logging subsystem when RENDER is missing. That is why journalctl and ~/.xsession-errors are silent.

4. Fix

setsid nohup xfwm4 --compositor=off >/tmp/xfwm4.log 2>&1 </dev/null &
xfconf-query -c xfwm4 -p /general/use_compositing -s false
export GTK_CSD=0

Pages build_type=legacy

legacy = branch-based Pages. GitHub serves what is pushed to main at /; .nojekyll prevents Jekyll. This is the standard mode for pre-built static HTML — it is not deprecated. The API requires a two-step enable on some repos (POST workflow, then PUT legacy) to avoid a documented 422.

Scripts

  • xfce-wm-fix.sh — reversible fix.
  • monitor.sh — snapshot + drift.
  • recover.sh — compare/verify + rollback plan.

Why not xfwm4 --replace --compositor=on?

It kills the working WM first. Without RENDER the replacement fails and you are left with no WM.
